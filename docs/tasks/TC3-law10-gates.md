# TC3: Law 10 gates — axiom-level native_decide/sorry/axiom gate

## Context

This task's substance lives in PLAN.md's Phase-1 history (the "Law 10 linter" entry, branch
`worktree-agent-a883598f71cb88e93`, commit `957c9a6` and its fix cycles); recorded here since
the task predates the current notes→design→review→implementation discipline (`design:
predates-discipline`). Law 10 (`docs/REVIEW.md`) restricts `native_decide` to propositions
universally quantified over their entire finite domain — a gate is needed because
implementations are generated by an untrusted, creative process (`docs/VISION.md` §2), and a
`native_decide` on a sampled or single-instance proposition is adversarially unsound.

This branch went through **four** adversarial review rounds, each of which found a real bypass
of the previous round's enforcement — a useful case study in why Law 13 insists a finding must
close its *class*, not its instance. Round 1 verdict: **REJECT AS GATE**. The classification of
all 41 `native_decide` occurrences in the tree at the time was verified honest, but the
reviewer found three live bypasses: `decide (config := .native)`-style invisible-to-regex
invocations; an auto-pass rule for anything named with an `_inst` suffix inside an
`Equivalence` file (which a bad actor could exploit by simply naming a real verification claim
`_inst`); and declaration-attribution inheritance through `example`/wrapped names (a
`native_decide` could hide behind a name the linter didn't associate with the offending
declaration). Fix cycle 1 (same agent) moved to axiom-oriented detection, deleted the
`_inst`-auto-pass rule entirely, made ambiguous attribution fail closed rather than pass, added
allowlist integrity checks (duplicate/stale entries fail), and added finite-forall syntactic
corroboration plus category-keyed citation warnings.

Fix cycle 1 landed as `24be5dd`; round 2 re-review verdict: **MERGE-WITH-FIXES** again — the
original three attacks were confirmed dead, but four *new* bypasses surfaced: a
`set_option`-prefixed invocation; comment-forged declaration heads that defeated the
staleness-detection logic; multiline or `(native := true)`-style configuration syntax the regex
didn't parse; and syntactic corroboration satisfiable by nothing more than a `-- ∀` comment
with no actual finite-domain proof behind it. The review's structural verdict was blunt:
**regex cannot hold this gate.**

Fix cycle 2 (`c842ecd`) is the architectural pivot this task is actually remembered for:
**an axiom-level gate**, `Tools/CheckGatesAxioms.lean` — a `lean_exe` that walks every compiled
declaration's kernel-recorded axiom dependencies (`collectAxioms`) rather than pattern-matching
source text. This is structurally un-bypassable by syntax games because it reads what the
*kernel* recorded a declaration actually depends on, not what the source text looks like. In
building it, the agent discovered toolchain-specific behavior the reviewer's own spec had
gotten wrong: Lean v4.33.1 emits *distinct* axiom names for native-evaluated `decide`
(`._native.native_decide.ax*`) versus the ordinary compiled `decide` path
(`._native.decide.ax*`) — the agent's empirical correction of the reviewer's substring
specification was itself verified right. The tool also found **13 declarations transitively
native-dependent via citation** (through `VerifiedProgram` wiring) that were invisible to any
text-scanning approach by construction — these got a new `axiom-only` allowlist category.
At that point: 4965 declarations audited, 54 native-dependent, 0 unallowlisted, ~40s wall time.
The Python regex scanner (`scripts/check_gates.py`) was hardened per the round-1/2 bypasses and
demoted to a secondary, faster pre-check rather than the load-bearing gate.

Round 3 verdict: **MERGE-WITH-FIXES** — the axiom-level architecture itself was accepted
(opaque/`implemented_by`/internal-aux laundering paths were verified closed, and the
reviewer's own alternate `ofReduceBool` spec was checked and found wrong, again confirming the
agent's empirical correction). The final fix cycle closed: FQN-keyed allowlist entries (a
bare-name collision attack had been demonstrated — two declarations sharing a short name could
shadow each other's allowlist entry); module-based scoping via `getModuleIdxFor?` (a
namespace-prefix trick had been shown to evade the prior scoping); the tool now reports **all**
axioms outside `{propext, Classical.choice, Quot.sound}`, including `sorryAx` and raw
hand-declared `axiom`s — this is called out explicitly in PLAN.md as **"implements the
previously-UNENFORCED zero-sorry/zero-axiom Pillar-1 requirement — a raw axiom currently sails
through both tools"** (i.e., before this fix, a bare `axiom` declaration was not actually caught
by anything); the Lean tool now honors allowlist categories and rejects malformed lines;
axiom-only entries get staleness validation; and a search-path/deprecation fix was applied.

A doc-wiring blocker tracked across three review rounds (REVIEW.md §4.1 item 4 / §4.4 Gate 1
needing to name both tools) closed on the integration branch: both `check_gates.py` and `lake
exe check_gates_axioms` are now named in `docs/REVIEW.md` (this was committed together with the
linter merge, per PLAN.md's merge-order note). One optional performance item was left open:
threading a `CoreM` seen-cache through `collectAxioms`.

## Deliverables & acceptance criteria

Historical — already merged to main. For the record: `Tools/CheckGatesAxioms.lean` walks
kernel-recorded axiom dependencies per declaration; any declaration depending on a
native-evaluation axiom or on any axiom outside the three permitted kernel axioms (including
`sorryAx` and raw `axiom`) must be allowlisted in `scripts/gate_allowlist.txt` under an honest,
FQN-keyed, module-scoped category; `scripts/check_gates.py` remains a fast secondary
source-level pre-check, not the load-bearing gate; `docs/REVIEW.md` §4.1/§4.4 name both tools
as required by Gate 1 of the approval state machine.
