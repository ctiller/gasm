# Apache-2.0 Header Allowlist
#
# Format (one entry per line, `::`-delimited, 5 fields):
#   <relative-file-path>::<category>::<added-date>::<added-by>::<justification>
#
# - <relative-file-path> is the whole in-scope file being exempted (a
#   license-header exception applies to an entire file, unlike
#   scripts/gate_allowlist.txt's per-declaration entries).
# - <added-date> is an ISO-8601 date (YYYY-MM-DD); <added-by> identifies
#   who/what added the entry (a person, or the reviewing agent/tool run).
# - Justification is free text and may itself contain `::`; the parser
#   splits with a bounded field count so that never breaks the format.
#
# category is one of:
#   third-party-embedded  - a first-party-tree file that verbatim-embeds
#                            third-party code under its own, different
#                            terms, so our Apache-2.0 header would be
#                            false/misleading if stamped on it.
#   generated-file         - a file that is mechanically (re)generated by
#                            a build/regen step, where a hand-maintained
#                            header would be stripped or overwritten and
#                            enforcing one here would just fight the tool
#                            that produces it.
#   no-comment-syntax      - an in-scope-by-extension file whose format
#                            has no native way to carry a comment header
#                            at all.
#
# Lines starting with '#' and blank lines are ignored.
#
# THIS FILE IS SEEDED EMPTY. As of the Apache-2.0 header rollout
# (2026-08-27), no first-party file in scope (Gasm/**/*.lean,
# Stdlib/**/*.lean, Spikes/**/*.lean, Tools/**/*.lean, root *.lean,
# scripts/*.py, scripts/*.ps1, scripts/*.sh, lakefile.toml) was found to
# embed third-party code, be mechanically generated, or lack comment
# syntax -- every one of them received a real header instead. Do not add
# an entry here to paper over an ordinary missing/malformed header;
# scripts/check_licenses.py's stale-entry check will hard-fail on an
# entry for a file that is (or becomes) fully compliant anyway.
